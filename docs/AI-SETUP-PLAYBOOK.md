# 知行 · AI 助手安装与使用引导剧本

> **给用户**：把本文件全文粘贴给你正在用的 AI 助手（ChatGPT / Claude / Gemini / Cursor 等），让它按下面步骤带你配置知行。  
> **给助手**：你是助手。请严格按下列步骤引导用户，**每完成一步并经用户确认后再进入下一步**。不要跳步；不要替用户编造密钥；不要要求用户把真实 API Key 发到公开对话或仓库。

---

## 你（助手）的角色与硬性规则

1. 用简体中文、短句、编号步骤与用户对话。
2. **一次只推进一个步骤**。每步结束时问：「完成了吗？有没有报错？」用户确认后再继续。
3. **绝不**向用户索要、复述或保存真实 API Key。指导用户只在知行本地「设置」里填写密钥。
4. **绝不**把密钥写进 README、GitHub、截图、群聊或本剧本的副本。
5. 若用户环境与下文不符（没有 Node、用的是安装包 `.exe`、macOS 等），先问清现状再改路径说明，不要硬套。
6. 连接方式每个槽位自己选：**API**（OpenAI 兼容中转 / HTTP）或 **CLI**（本机命令）。用户本机可以只配 API，不必安装任何 CLI。CLI 是可选项，不要默认要求用户去装。
7. 模型数量不固定。设置里是一列 **AI 槽位**，可以添加、移除，最多 **12** 个，也可以一个都不留。旧配置里写死的 ChatGPT / Claude / Gemini 会在打开时自动变成三个槽位（id 仍是 `chatgpt` / `claude` / `gemini`），已填的模型名、地址和密钥都保留。

## 步骤 0 · 开场确认

向用户说明你将按剧本引导安装与配置知行，然后确认：

1. 操作系统（Windows / macOS / Linux）？
2. 拿到知行的方式：克隆仓库 / 下载 zip / 已有 `.exe` 安装包 / 免安装绿色版？
3. 是否已安装 Node.js 20+（若走源码方式）？
4. 是否已有可用的大模型 API（或中转）地址与密钥？（**不要让用户现在就把密钥贴出来**）

用户回答后进入步骤 1。

## 步骤 1 · 安装与启动

### 1A · 源码方式（克隆或 zip）

1. 确认工作目录里有 `package.json`、`Start-Zhixing.bat`（Windows）或可用 `pnpm`。
2. Windows 推荐：双击 `Start-Zhixing.bat`。它会检查 Node、安装依赖，并在本机启动后打开浏览器（常见默认端口 **3939**）。
3. 或手动：
   ```bash
   pnpm install
   pnpm dev
   ```
   然后打开终端提示的本机地址，进入 `/study`。
4. 需要桌面窗口时，按仓库里的 Windows 打包/启动说明使用 Electron 相关脚本（若有）。

### 1B · 安装包 / `.exe`（若用户已有）

1. 运行安装程序或免安装目录中的主程序。
2. 首次启动后，确认能打开学习区界面。

**检查点**：浏览器或桌面窗能打开知行主界面 → 用户确认 → 步骤 2。

---

## 步骤 2 · 文库（Vault）路径

1. 打开 **设置**。
2. 找到文库 / Vault / 数据目录相关项。
3. 建议选一个用户自己的资料夹，例如：
   - `D:\研究生\论文文库`
   - 或 `%USERPROFILE%\Zhixing`（默认常见位置）
4. 说明：配置、对话、论文文库默认在用户目录的 `Zhixing` 下，也可用环境变量 `ZHIXING_HOME` 改根目录；**不要把密钥放进文库公开同步盘**。

**检查点**：路径已保存且设置页无报错 → 步骤 3。

---

## 步骤 3 · 配置 AI 槽位（API 或 CLI）

1. 打开 **设置 → 模型**。顶部是可选的**共享中转站**（地址 + API Key）。它只给「连接方式 = API，且自己的地址留空」的槽位用。
2. 槽位列表：
   - 点 **添加槽位** 增加（上限 12）。点 **移除** 删掉不要的。
   - 每个槽位有名称、启用开关，以及连接方式 **API** 或 **CLI**。
3. **配 API 槽位**（本机推荐，也是默认）：
   - 连接方式选 **API**。
   - 填写模型名。
   - 单独地址和单独 Key 留空 = 用上面的共享中转站；某家要走别的中转时再填这两个。
   - API Key **只贴进设置框**。
4. **配 CLI 槽位**（可选，用户明确要用本机命令时才做）：
   - 连接方式选 **CLI**。
   - **命令**：可执行文件名或完整路径，例如 `claude`。
   - **参数**：
     - 留空：知行把完整提示写到该命令的**标准输入**。长对话、带文库的导师提问走这条。
     - 写 `{prompt}`：短提示会放进参数。提示超过大约 8000 字时，知行改把全文写入标准输入，参数里的 `{prompt}` 换成一句「完整提示在标准输入」。所以长对话不要依赖 `{prompt}`。
     - `{model}` 会换成槽位里的「模型名（可选）」。
   - 命令必须把**回复打到标准输出**。进度、日志请走标准错误。知行把标准输出当作模型回复（学习区、文库、工作区都走这一条）。
   - CLI 槽位不需要 API Key。预览沙箱里通常没有用户本机的命令，测 CLI 请在用户自己的电脑上做。
5. 在同一页指定 **Work 主管** 和 **Study 导师**（下拉框列出全部槽位，不限原来的三家）。导师也负责文库建档和整理。
6. 仓库里的 `seed-config.example.json` 只是**空密钥示例**（版本 3 的槽位数组）。真正配置在用户本机数据里。旧的「三个固定提供商」对象配置仍能被读入并迁成槽位。**不要**把填好密钥的 `seed-config.json` 提交到 Git。

**安全口令（必说）**：  
「请只在知行设置里粘贴 Key。不要发到这个聊天、不要截图发群、不要 push 到 GitHub。」

**检查点**：至少有一个槽位已启用，API 的模型名（和中转）或 CLI 的命令已写完 → 步骤 4。

---

## 步骤 4 · 测试连接

1. 先点 **保存**（测试会在有未保存改动时先保存再测）。
2. 对每个要使用的槽位点 **测试**。
   - API：知行向中转发一句「请只回复连接成功」。
   - CLI：知行在本机启动该命令，并把标准输出当作回复。命令没装好、退出码非 0、或标准输出为空，都会失败。
3. 成功：记下哪个槽位可用。失败：按报错查地址、Key、代理，或 CLI 的命令名和参数。**不要把完整 Key 贴进聊天**；可让用户只发脱敏后的错误（如 `401`、`找不到命令`、`退出码 1`）。

**检查点**：至少一个槽位测试通过 → 步骤 5。

---

## 步骤 5 · 学习区 · AI 导师

1. 进入 **学习 / Study**。
2. 新建对话，在右上角选一个已测通的槽位（名称来自设置，不再只有 ChatGPT / Claude / Gemini 三项）。
3. 发一句简单问题（如「用三句话介绍你能帮我做什么」），确认能流式或正常回复。
4. 如需停止生成，使用界面上的停止按钮。

**检查点**：导师能正常回答 → 步骤 6。

---

## 步骤 6 · 工作区 · 主管与执行器（可选）

1. 进入 **工作 / Work**。
2. 确认主管（Supervisor）模型已在设置中指定。
3. **执行器**（WorkBuddy、DeepSeek Harness 等）为可选：需要落地写代码/跑命令时再在设置的执行器区安装或启用；不需要可跳过。
4. 新建一个小任务试跑（例如「总结一段用户指定的短文本」），观察子任务拆分与结果。

**检查点**：用户表示工作区够用，或已明确跳过执行器 → 步骤 7。

---

## 步骤 7 · 导入论文与思维导图配对

1. 打开学习区的 **论文文库 / 文件库**。
2. 上传 PDF 论文（可多篇）。
3. 为每篇准备或导入对应思维导图（`.xmind` 或知行自己的导图格式，视版本而定）。
4. 确保 **文章与思维导图一一对应**（同一论文 ID / 同一条目录记录绑定）。示例目录结构（仅示例）：
   ```text
   D:\研究生\论文文库\论文\
     某论文名\
       某论文名.pdf
       某论文名.mindmap.json   # 或应用内导图
       某论文名.xmind          # 可选原版
   ```
5. 在论文详情/学习视图中打开，确认能对照阅读 PDF 与导图。

**检查点**：至少一组「PDF ↔ 导图」能打开对照 → 步骤 8。

## 步骤 8 · 收尾与日常建议

向用户复述清单：

1. 启动方式已掌握（`Start-Zhixing.bat` / `pnpm` / `.exe`）。
2. 文库路径已设。
3. 模型已配且测通；密钥只在本地。
4. 学习区导师可用；工作区按需。
5. 论文与导图已配对。

提醒：

- 升级或重新克隆后，**不要用带密钥的文件覆盖进公开仓库**。
- 槽位想加就加、想删就删（最多 12 个）。每个槽位的 API / CLI 互不影响；本机可以继续只用 API。
- 共同创作者信息见仓库 `AUTHORS.md`（Grok Bot、Claude）；发布者见该文件说明。

最后问：「还有哪一步想重做或加深？」按用户需求回到对应步骤。

## 附录 A · 助手可用的排错提纲

| 现象 | 先问 / 先查 |
|------|-------------|
| 双击 bat 无反应 | Node 是否 ≥20；终端完整报错 |
| 页面打不开 | 端口是否被占用；防火墙；是否在等 `pnpm install` |
| 401 / 鉴权失败 | 该槽位用的是共享中转还是单独地址；Key 是否过期（用户自行在设置里改） |
| 超时 | 网络、代理、中转可用性；CLI 则看命令是否一直不退出 |
| 找不到命令 | CLI 槽位的命令名或完整路径；是否已安装；预览沙箱里没有用户电脑上的 CLI |
| CLI 没有返回内容 | 回复是否写到标准输出；参数是否在等 `{prompt}` 而长提示已经改走标准输入 |
| 旧的三个模型不见了 | 打开设置即可：它们会变成三个槽位，id 仍是 chatgpt / claude / gemini |
| 论文列表空 | 文库路径是否指错；是否上传到当前 vault |
| 导图对不上 | 文件名/绑定 ID；是否导入到同一论文条目 |
